# FF2 monsters — the name table

Generated by `tools/ff2-monster-catalog.mjs`.

Table: bank 5, file `0x16c54`, 2 bytes LE per id, pointing at a
`00`-terminated string. **128 entries**, Leg Eater through the Emperor.

⛔ **Verification.** This table is not pinned to an instruction — FF2's battle
code has not been traced. It is confirmed a different way: object types 73-76
are monster GUARDS that name their monster in dialogue and then start the
fight (found by `ff2-type-sweep.mjs`). Talking to each and reading the battle
screen gives four confirmations spread across the table, each agreeing with

## Stats

⭐ **HP is not stored as a number anywhere.** Record byte 0 is an INDEX into
a shared 16-bit value pool — searching the whole ROM at every stride 1-32 for
Adamantoise's 450 returns nothing, because the record only holds `0x0E`.
Every later byte packs TWO 4-bit indexes resolved through 16-entry tables.

```
12/$9962  LDA $04 / ADC #$C3       ; record base $87C3 + monster*10
12/$9972  ASL A / ADC #$C3 / #$8C  ; -> the VALUE POOL at $8CC3, idx*2
12/$997E  LDA ($78),Y -> $4E,$52   ; ...that is HP
12/$998D  LDY #$02, same pool      ; record byte 1 -> MP
12/$99B4  JSR $FD07                ; later bytes: a NIBBLE split into
12/$99B8  LDA $8D03,Y / $8D13,X    ; 16-entry tables
12/$9A3C  CPX #$30                 ; 48 bytes per enemy in RAM, x8
```

| table | where | per entry |
|---|---|---|
| stat record | bank 12 `$87C4`, file `0x307d4` | 10 bytes |
| value pool | bank 12 `$8CC3`, file `0x30cd3` | 2 bytes LE |

⛔ **Only HP is behaviourally proven** — the pool value matches the HP the
battle loads, the RAM byte counts down when the monster is hit, and patching
the index changes the HP that loads (`0x00` → 0, `0xFF` → 28282). MP is read
from the same pool by the instruction after HP's, but was not separately
tested. The nibble-packed bytes 2-9 measurably affect combat (zeroing byte 5
tripled the damage the party dealt) but are **left unnamed rather than
guessed at**.
